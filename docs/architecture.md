# 構成と実装の読み方

## 処理の流れ

1. ChatGPTがSitesによって作成された専用プラグインを呼び出す。
2. Sitesが利用者を認証し、対象Siteを閲覧できるかを確認する。
3. Workerが `POST /mcp` を受け取る。
4. JSON-RPCの `method` と `params.name` から処理を選ぶ。
5. サーバーの `COSENSE_PAT` を `x-personal-access-token` ヘッダーへ付け、Cosense APIへ通信する。
6. 必要な情報を整形し、MCPの `content` ブロックとして返す。

Web画面とMCPは同じWorkerで動きます。データ本体はCosenseにあり、DB・ファイルキャッシュ・サーバー側LLMは使いません。

## 担当する範囲

| 担当 | 提供する機能 |
| --- | --- |
| Cloudflare Workers | JS/TS由来コードの実行、HTTP受付、fetch、Web Crypto |
| OpenAI Sites | Site作成、配信URL、非公開アクセス制御、シークレット設定、バージョン保存とデプロイ、専用プラグインとの連携 |
| このコード | MCPツール定義と実行、入力検証、Cosense APIの呼び出し、結果整形、編集用の署名付きトークン |
| Cosense | ページ保存、検索、関連情報、履歴、編集プレビュー、編集確定 |

Sitesの認証基盤・配信設定自体を、このリポジトリで再実装しているわけではありません。

## MCPの範囲

Sitesの現行契約に合わせた、ステートレスなJSON-RPCエンドポイントです。`server/discover` は `2026-07-28` を返し、`tools/list` と `tools/call` に対応します。一般のMCPクライアント向けのOAuth discovery・セッション管理・SSE・旧版 `initialize` 互換を網羅する汎用MCPサーバーではありません。

ツールのJSON Schemaと同じ定義を使い、サーバーでも入力を検証します。読み取りモードでは書き込みツールを一覧から除き、直接名前を指定しても拒否します。

## プレビューから書き込みまで

新規ページは1行目をタイトルとした本文、既存ページは実際のpageId・lineIdを使った行操作を受け取ります。Cosenseのpreview APIへ操作を送り、変更後の本文を返します。この時点でページ本文の変更は確定していません。

返却する `previewToken` は、previewId・プロジェクト・利用者・有効期限を含むHMAC-SHA256署名付きデータです。鍵はPATから用途を分けた文字列を付けて作成します。これは独立したシークレット管理基盤の代替ではありません。PATを変更すると未確定トークンも使えなくなります。

確定時に署名・利用者・プロジェクト・期限を検証し、CosenseへpreviewIdを送ります。最大5分の期限と一度だけの確定、プレビュー後の編集競合はCosense側の仕組みも利用します。ローカルDBにプレビューを保存しません。

通信失敗や上流5xxでは、確定済みか判断できないため `WRITE_OUTCOME_UNKNOWN` を返し、自動再実行しません。409は `WRITE_CONFLICT`、消費済みや期限切れの404は `PREVIEW_EXPIRED_OR_USED` です。

署名は「ユーザーが承認した」という証明ではありません。実行するエージェントは、ユーザーから依頼された変更か、プレビューがその依頼と一致するかを確認する必要があります。

## 信頼境界

`oai-authenticated-user-id` は、Sitesが認証・権限チェック後に渡すことを前提としています。このコードはそのヘッダー自体の署名を検証しません。直接公開したWorkerでは、第三者が同名ヘッダーを送れるため認証になりません。

PATは所有者の閲覧可能範囲を持ちうるので、この実装は対象を設定済みの1プロジェクトに固定します。上流通信先は固定origin、リダイレクトは追いません。ファイル情報は返却projectNameも検証します。

エラー本文に上流レスポンス・PATを含めず、アプリのconsoleログは追加していません。プラットフォーム側の運用ログまで無効化する設定ではありません。
